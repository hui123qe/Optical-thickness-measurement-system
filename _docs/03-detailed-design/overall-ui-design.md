# 总体 UI 设计

## 1. 设计依据和状态

### 已确认或已有输入

- C++20、Qt 6.5.3、MSVC，支持 Debug 和 Release。
- 界面风格要求极简、稳定、清晰。
- 采用左侧导航、顶部常驻区域、右侧常驻区域、中央工作区和底部状态栏。
- 功能页面统一在中央工作区显示。
- UI 只展示状态和提交用户意图，不直接持有运动控制器、激光探头或其他设备句柄。

### 当前缺失

- 仓库中的 Qt UI 原型用于验证本文所述布局，尚未连接运动控制器、激光探头或业务工作流。
- 本文和界面原型状态为 `draft / in-progress / unverified`。

## 2. 总体布局

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ 顶部常驻区：系统名称｜绝对坐标｜相对坐标｜运行状态｜软件急停          │
├──────────────┬───────────────────────────────────┬───────────────────────┤
│              │                                   │ 右侧常驻状态区        │
│ 左侧导航栏   │                                   │                       │
│              │       中央工作区                  │ • 运动控制连接        │
│ 主界面       │       QStackedWidget              │ • 激光传感器状态      │
│ 日志记录     │                                   │ • 当前任务状态        │
│              │       一次只显示一个页面          │ • 报警/简短提示       │
├──────────────┴───────────────────────────────────┴───────────────────────┤
│ 底部状态栏：公司标识｜软件版本｜系统状态｜简短提示｜日期时间             │
└──────────────────────────────────────────────────────────────────────────┘
```

## 3. 区域设计

### 3.1 主窗口

建议使用 `QMainWindow` 作为顶层窗口：

- 中央区域承载总体布局；
- 底部使用 `QStatusBar` 或独立状态 `QWidget`；
- 统一管理窗口标题、尺寸变化和页面切换；
- 不在主窗口中实现运动、测量或设备通信逻辑。

### 3.2 左侧导航栏

- 使用纵向轻量按钮列表、`QListWidget` 或单一导航 `QWidget`。
- 每个入口只负责切换中央页面。
- 当前页面使用背景色和左侧强调条表示选中。
- 功能入口使用短名称，不在导航中显示业务参数。
- 固定提供“主界面”“日志记录”两个入口。
- 安全保护属于业务层和设备层约束，不作为页面或导航入口。

### 3.3 顶部常驻区域

顶部区域建议从左到右排列：

1. 系统名称或当前页面名称；
2. 当前任务简短状态；
3. 绝对坐标组；
4. 相对坐标组；
5. 全局运行状态；
6. 软件急停入口。

坐标显示设计为可配置轴列表：

- 已确认的运动轴默认显示 X、Y；
- 如果后续确认 Z 为有效显示量，可在同一坐标组件中增加 Z，不改变总体布局；
- 每个坐标值必须标明绝对/相对属性和单位；
- 坐标标题和数值使用放大字号，确保在顶部常驻区域中清晰可辨；
- 坐标更新不依赖当前活动页面。

### 3.4 中央工作区

- 使用 `QStackedWidget` 管理功能页面。
- 每个页面优先实现为独立 `QWidget`。
- 页面只显示当前任务需要的输入、主要操作、结果和局部状态。
- 共用坐标、连接、版本和时间不在每个页面重复显示。

### 3.5 右侧常驻状态区

按从上到下的顺序显示：

1. 运动控制连接；
2. 激光传感器连接和数据有效性；
3. 当前任务名称及阶段；
4. 当前报警或故障摘要。

状态展示遵循：正常为绿色、等待或警告为橙色、故障为红色、未知或离线为灰色。顶部软件急停只提交软件意图，不能替代物理急停。

### 3.6 底部状态栏

建议从左到右显示：

- 公司标识；
- 软件版本；
- 系统运行状态；
- 最近一条简短提示；
- 当前日期和时间。

底部状态栏只显示摘要，不承载复杂操作。

## 4. 页面设计矩阵

| 导航页面/标签页 | 主要输入 | 中央工作区主要内容 | 主要输出/反馈 |
| --- | --- | --- | --- |
| 主界面 / 手动控制 | 键盘、鼠标、界面按钮的点动意图，目标坐标 | 三轴点动、目标点移动、运动参数、当前点位置导出 | 当前运动状态、方向、目标点和操作结果 |
| 主界面 / 自动化操作 | 配置名称、已保存配置、矩形阵列、圆形阵列或 `csv` 坐标文件的对应参数 | 配置管理区，以及回零、测试开始、终止动作区 | 配置确认状态、任务配置摘要和任务结束状态 |
| 日志记录 | 完成时间范围、关键词和记录选择 | 自动化任务类型、唯一完成时间、任务结果和说明列表 | 查询结果；选中“完成”记录后的数据导出入口 |

坐标显示属于顶部常驻区域，不单独占用页面。阵列扫描、自动测量和当前点导出均作为主界面的任务内功能，不再占用左侧导航入口。

## 5. 关键页面布局建议

### 5.1 主界面

主界面内部使用 `QTabWidget` 提供“手动控制”和“自动化操作”两个标签。标签只切换操作方式；正在执行的任务状态由业务工作流保持，不因切换标签而销毁。

#### 手动控制标签

- 主区域：X/Y/Z 三轴点动控制、目标点输入和当前运动模式。
- 次要区域：步长、速度等输入配置。
- 当前点位置导出作为本标签内的次要操作，仅导出当前绝对/相对坐标快照。
- 键盘、鼠标和界面按钮最终都转换为相同的用户运动意图。
- UI 不直接调用运动卡 SDK。

#### 自动化操作标签

```text
┌──────────────────────────────────────────┬───────────┐
│ 任务配置                                 │ 动作      │
│ [加载配置] [保存配置]                    │ [回零]    │
│ 任务模式：[矩形 / 圆形 / CSV]            │ [测试开始]│
│ 对应配置项                               │ [终止]    │
│ [重置配置] [确认配置]                    │           │
└──────────────────────────────────────────┴───────────┘
```

- 参数采用标签页内常驻输入配置区，任务模式改变时仅显示该模式对应的配置项。
- 点击“测试开始”后只显示只读任务摘要确认，不在确认框中编辑参数。
- 自动化操作提供“矩形阵列”“圆形阵列”和“加载 CSV 文件”三种模式；只有 CSV 模式显示文件选择入口。
- 任务配置与动作使用两个独立区域；动作区提供回零、测试开始和终止入口。
- 配置区主界面只显示保存、加载、确认和重置入口，不显示测点预览。加载配置弹窗包含已保存配置下拉框，保存配置弹窗包含配置名称输入框。
- 目标交互规则为：配置确认后才能用于实验，确认后保持锁定，只有重置后才能修改。当前阶段只实现控件与布局，配置存储、加载、锁定和实验许可逻辑待后续指导。
- 用户切换页面或标签时，自动测量任务状态由工作流保持，不由页面对象持有。

### 5.2 日志记录页面

- 每条记录对应一次完整自动化任务，不记录任务内的单个动作。
- 表格仅显示任务类型、唯一完成时间、任务结果和说明；任务类型为矩形阵列、圆形阵列或加载 CSV 文件。
- 任务结果统一使用“完成”“失败”“终止”。
- 导出区域位于页面顶部；只有选中结果为“完成”的记录时，才启用该记录的数据导出入口。
- 时间范围和关键字查询位于同一水平筛选区域，不提供动作、任务类型或结果筛选。
- 失败记录显示错误摘要，但不伪装为完成记录。

### 5.3 安全约束

- 安全保护不设计为可进入的界面。
- Z 轴允许范围由全局配置提供，并由业务层和设备层在执行前强制校验。
- UI 可根据业务层返回结果禁用操作或显示越界原因，但不得成为唯一安全保护措施。

## 7. UI 与业务边界

```text
用户操作
  ↓
页面 QWidget：校验输入并提交用户意图
  ↓
业务/工作流服务：决定能否执行和执行顺序
  ↓
运动、激光、日志、数据服务
  ↓
状态和结果通过信号/事件返回 UI
```

- UI 不持有设备句柄。
- UI 不自行实现重试、运动时序或测量循环。
- UI 不因页面切换而停止或销毁正在执行的业务任务。
- 所有运动和测量意图在提交前显示明确目标。
- 故障状态由业务层提供，UI 负责准确呈现。
- Z 轴范围和其他安全约束由业务层/设备层强制执行，界面不提供安全保护页面，也不允许绕过约束。

## 8. 视觉规范

### 颜色

- 主背景：白色或浅灰色。
- 主强调色：深蓝或工业蓝，用于导航选中和主要操作。
- 正常：绿色。
- 等待/警告：橙色。
- 故障/禁止：红色。
- 离线/未知：灰色。

### 字体与信息密度

- 优先使用系统清晰无衬线字体。
- 页面标题、区域标题、正文和状态信息保持固定层级。
- 坐标和测量数值使用等宽数字或保持列宽稳定。
- 避免大段说明文字；详细原因放到日志或详情区域。

### 控件原则

- 同一动作只保留一个主要入口。
- 主要动作使用文字按钮，不只依赖图标。
- 运动和测量操作与普通页面切换在视觉上区分。
- 禁用状态必须可辨识，并提供必要原因。

### 滚动条可见性约束

- 该表格的垂直滚动条固定使用 `Qt::ScrollBarAlwaysOn`，不以当前行数决定是否显示；
- 滚动条轨道、滑块和上下按钮仅使用控件专属样式，不改变其他表格；
- 上下箭头使用应用资源中的固定图形，不依赖操作系统是否绘制原生箭头；
- 没有可滚动内容时允许滚动条处于禁用状态，但完整轨道和上下按钮仍需可见；
- 两列宽度继续随表格宽度拉伸，水平滚动条保持按需显示。

## 9. 状态设计

总体状态建议最少包含：

- `Offline`：必要设备未连接；
- `Ready`：系统可接受操作；
- `Running`：运动或测量任务执行中；
- `Terminated`：用户终止或任务被系统终止；
- `Completed`：动作或任务正常完成；
- `Fault`：存在故障，需要处理后才能继续。

该状态集合是 UI 展示建议，最终名称和状态转换应以业务工作流定义为准。

## 10. 待确认后再细化的设计

- 顶部坐标组件最终显示 XY 还是 XYZ。
- 鼠标控制是点击点动、按住连续移动，还是画布拖动。
- 目标屏幕分辨率、缩放比例和是否触摸操作。
- 当前点位置与已完成任务记录的导出文件格式。
- CSV 字段、坐标单位和无效行处理规则。
- 自动测量是否需要暂停/继续；当前设计仅提供开始和终止。
- Z 轴全局范围配置的文件位置、单位和变更权限。

这些问题不阻塞总体布局，但会影响对应页面的详细交互设计。

## 11. 验证计划

- 静态评审总体布局和页面职责。
- 使用低保真原型验证导航、常驻状态和页面信息密度。
- 使用模拟数据验证坐标、连接、任务和故障状态展示。
- 在用户确认每个页面交互后，再进入 Qt 页面实现。
- 本文未进行编译、界面运行或设备验证。
