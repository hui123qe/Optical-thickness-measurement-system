# 物理设备 CL-3000 调试

本文整理物理 CL-3000 调试中已经涉及的网络、SDK、外部端子、控制、
测量数据与零点知识。内容以当前调试现象为边界；尚未取得官方定义的部分，
仍需结合当前 SDK 版本的头文件和手册确认。

## 1. 网络与 IP

### 1.1 BOOTP 与固定 IP

- `BOOTP`：设备每次启动时通过 BOOTP Server 获取 IP；
- `固定 IP 地址`：设备每次启动时直接使用控制器中保存的 IP；
- `BOOTP → 固定 IP 地址`：先通过 BOOTP 获得 IP，再保存为固定 IP，后续启动直接使用。

### 1.2 MAC 与 IP 的区别

- MAC 是设备网卡的二层地址；
- IP 是 IPv4 网络地址，可以由厂家预设、用户设置或 BOOTP/DHCP 分配。

即使网口已协商出 `100 Mbps`，也只能证明 PC 与 CL-3000 的物理链路已经建立，
不能证明双方已经可以进行 IPv4 通信。

### 1.3 当前抓包观察

Wireshark 中曾观察到 KEYENCE 设备周期性发送：

```text
ARP Announcement for 196.168.0.10
```

这表示控制器当时正在声明 `196.168.0.10`。电脑当时使用 `192.168.0.88`；
若双方掩码均为 `255.255.255.0`，则 `192.168.0.0/24` 与
`196.168.0.0/24` 不属于同一子网。因此可能出现网口显示已连接，
但 `Get-NetNeighbor` 中没有正常 IP 与 MAC 邻居关系的现象。

`196.168.0.10` 与常见的 `192.168.0.10` 很接近，后续配置时应重点确认
是否存在误设置。

### 1.4 IP 配置记录与遗忘后的找回

设备 IP 配置完成后容易因未留存记录而遗忘。每次设置或修改 IP 时，应同时记录：

- 设备或控制器编号；
- 设置后的 IP 地址、子网掩码和端口；
- 设置时间与操作人员；
- 对应的感测头、程序号和使用场景。

如果已经遗忘设定值，可以优先通过串口连接读取控制器中保存的 IP 配置。串口读取前
仍需核对连接参数和设备编号，避免把其他控制器的配置误认为目标设备配置。

如果暂时无法通过串口确认，可在控制器重启期间使用 Wireshark 抓包。设备启动时可能
发送 ARP Announcement 等广播报文；分析报文中声明的源 IP，可以辅助判断控制器当前
设定的 IP。抓包所得地址应再与设备标签、串口读取结果或实际连通性测试交叉确认，
不能只依据一次广播就直接修改现场网络配置。

## 2. SDK 中的 deviceId

`deviceId` 更适合理解为 DLL 内部的设备连接编号或会话槽位，而不是 IP、MAC
或探头编号。例如：

```text
deviceId = 0 -> CL-3000 A
deviceId = 1 -> CL-3000 B
deviceId = 2 -> CL-3000 C
```

同一台控制器从建立连接到后续所有 API 调用，应保持使用同一个 `deviceId`。

## 3. CL-NavigatorN 外部端子配置

当前调试截图中看到：

```text
输入 12 -> 发光停止
输入 13 -> 测量停止
```

即相应端子输入有效时，控制器执行停止发光或停止测量功能。

### 3.1 输入极性

`N.O.` 和 `N.C.` 描述输入信号的有效逻辑：

- `N.O.`（Normally Open，常开）：端子有效或导通时触发功能；
- `N.C.`（Normally Closed，常闭）：有效逻辑相反，常用于断线检测或安全回路。

输入极性决定什么电气状态算“输入有效”，与该输入被分配为何种功能是两个概念。

## 4. 增加外部端子会影响软控制

当前现象为读取测量数据正常，但调用发光控制和测量控制接口时返回
`CL3IF_RC_ERR_UNIQUE_ERROR1`。正常读取已经成功，说明通信连接本身大概率正常。

当前重点怀疑：外部端子已经分配“发光停止”和“测量停止”功能，导致 PC 端的
软件控制命令受到限制或与端子状态冲突。建议按以下顺序排查：

1. 检查输入 12、输入 13 的功能分配和当前有效状态；
2. 临时取消或修改对应外部输入功能；
3. 将新配置写入控制器；
4. 再次调用相应 SDK 控制接口；
5. 若仍失败，再重启控制器后验证；
6. 最终以当前 SDK 版本手册中对应 API 的返回码和固有错误说明为准。

外部端子分配与该错误之间目前属于高可能性判断，尚未得到官方错误定义或对照实验的
最终确认。

## 5. 自动置零 Auto Zero

自动置零的作用是将当前有效测量位置设为新的零点。设置前应确认设备已连接、
目标输出编号有效，并且当前测量值有效；条件满足后，对指定输出启用 Auto Zero。

例如，设置零点前当前位置的原始测量结果为 `12.345 mm`，设置后该位置显示为
`0.000 mm`。随后位置变化到原始值 `12.445 mm` 时，相对结果约为 `+0.100 mm`。

清除零点是取消此前建立的 Auto Zero 偏移，使指定输出恢复到原始测量基准。
因此两项操作是一组相反逻辑：

```text
设置零点：保存当前有效位置作为零点，后续结果相对此零点输出
清除零点：删除已保存的零点偏移，恢复原始测量基准
```

设置和清除均只作用于指定输出，准确的生效条件、保持方式及掉电行为仍应以当前
控制器配置和 SDK 手册为准。

## 6. 复位输出与置零的区别

以下概念不能混用：

```text
Auto Zero
= 改变测量基准
= 将当前位置作为 0

清除零点
= 删除 Auto Zero 偏移
= 恢复原始测量基准

Reset / 复位输出
= 恢复某些输出、保持、判定或异常状态
```

因此，复位输出不等于把测量值变成零。复位输出具体会清除哪些状态，取决于
CL-3000 当前输出、保持和判定配置以及对应 API 定义。

## 7. 测量数据结构

一帧测量数据可理解为：

```text
一帧测量数据
│
├─ addInfo
│  ├─ triggerCount
│  └─ pulseCount
│
└─ outMeasurementData[8]
   ├─ OUT1
   ├─ OUT2
   ├─ ...
   └─ OUT8
```

## 8. CL3IF_ADD_INFO

数据结构包含 `triggerCount` 和 `pulseCount`。

### 8.1 triggerCount

未使用编码器触发时，可用于描述触发发送计数，帮助上位机检查测量帧是否连续、
是否存在丢帧。

### 8.2 pulseCount

使用编码器触发时，表示本次测量触发时的编码器脉冲位置。该值可以将编码器位置
与 CL-3000 测量值关联，用于构建“位置 → 厚度”的轨迹测量数据。

## 9. CL3IF_OUTMEASUREMENT_DATA

每个输出的测量数据主要包含：

```text
measurementValue：整数形式的测量结果
valueInfo：测量值当前的有效性或测量状态
judgeResult：HI / GO / LO 等判定结果
```

### 9.1 measurementValue

`measurementValue` 是整数形式的原始结果，不是直接的 `double mm`。实际物理值通常由
原始整数与当前最小显示单位共同确定。

当前软件不会把 `measurementValue` 直接当作厚度，也不再使用人工配置的固定换算系数。
每次测量会先读取控制器当前程序，再读取该程序和当前 OUT 对应的最小显示单位，最后
计算：

```text
最终测量值（mm） = measurementValue × 最小显示单位（mm/count）
```

## 10. 最小显示单位

例如最小显示单位为 `0.001 mm` 时：

```text
raw 1    = 0.001 mm
raw 1000 = 1.000 mm
raw 1234 = 1.234 mm
```

最小显示单位是数据展示或输出的最小刻度，不等同于设备的分辨率、重复性或测量精度。
例如最小显示单位为 `0.001 mm`，不代表测量精度就是 `±0.001 mm`。

最小显示单位可能随 CL-NavigatorN 中的程序和 OUT 配置变化。当前软件通过
`CL3IF_GetProgramNo` 获取实际程序号，再通过 `CL3IF_GetDisplayUnit` 读取对应 OUT 的
最小显示单位，避免软件配置与控制器设置不一致。

设备调试页同时显示原始值、最小显示单位和计算后的毫米值。自动测量数据库也同步保存
这三项数据：`raw_value`、`display_unit_millimeters` 和 `thickness_millimeters`，Excel
导出沿用相同单位和数据来源。

## 11. valueInfo

`valueInfo` 描述 `measurementValue` 当前是否有效以及处于什么测量状态；
它与 `judgeResult` 的上下限判定不同。例如：

```text
measurementValue = 10200
valueInfo        = Valid
judgeResult      = HI
```

该结果表示测量值本身有效，但超过判定上限，因此 `HI` 不等于 `Invalid`。

当前尚未取得 `valueInfo` 的完整官方枚举和数值定义，精确映射仍需结合当前版本的
`CL3_IF.h` 或官方手册确认。

## 12. judgeResult

`judgeResult` 表示测量结果与设定上下限之间的判定，典型结果为 `HI`、`GO`、`LO`。
例如下限为 `9.900 mm`、上限为 `10.100 mm` 时，`10.050 mm` 可能判定为 `GO`，
`10.200 mm` 可能判定为 `HI`；两者的 `valueInfo` 都可能为有效。

`judgeResult` 的完整枚举和数值定义同样应以当前 SDK 版本的头文件或官方手册为准。

## 13. 测量环境与前期准备

当前激光探头的工作环境和待测物条件较严格。现场调试记录的基本条件为：

```text
待测物放置面：稳定、平整的基准平面
基准平面到激光探头的距离：10 mm ± 0.3 mm
待测物厚度要求：1 mm
```

以上数值是当前现场测试条件记录。在用于其他探头、量程或程序前，应先核对对应型号、
感测头设置和官方规格，不能直接作为所有 CL-3000 配置的通用参数。

### 13.1 测试准备

满足安装距离和物料厚度要求通常需要多项前期操作：

1. 准备尺寸和厚度明确的待测物或标准件；
2. 确认承载平面平整、稳定且没有明显倾斜；
3. 调整探头与基准平面的相对位置，使距离进入允许范围；
4. 核对待测物厚度是否满足当前测试条件；
5. 确认探头、控制器程序和测量输出选择正确；
6. 待光学状态稳定后，再检查软件测量值和数据有效状态。

当前现场使用标称厚度 `10 mm` 的标准块辅助准备测试环境。该标准块具体用于建立
探头到基准平面的距离、校验安装位置，还是验证其他尺寸条件，尚需结合现场操作步骤
进一步确认；它不能直接替代对 `1 mm` 待测物厚度条件的核对。

### 13.2 绿光状态

当安装距离、反射条件等满足当前测量要求时，探头会发出绿光。绿光可作为现场调整时的
直观参考，但不应作为测量有效的唯一依据。开始记录结果前，还应同时确认：

- 软件处于正确的测量状态；
- `valueInfo` 表明数据有效；
- 测量值稳定且没有超量程；
- 当前程序、输出通道和感测头选择正确。

## 14. 多感测头选择风险

一个控制器可以支持多个感测头。即使某个感测头没有实际连接，控制器或配置软件中仍
可能允许选择该感测头。因此，“界面允许选择”不表示“对应物理感测头已连接并可用”。

选择错误的感测头可能导致测量数据错误、异常或与实际物理通道不对应。开始调试前应
依次核对：

1. 物理连接的感测头接口；
2. 控制器当前选择的感测头编号；
3. CL-NavigatorN 中对应程序的感测头配置；
4. SDK 或上位机读取的输出通道；
5. 返回数据是否与当前标准件和安装位置相符。

当数据异常但通信正常时，应把“感测头选择错误”列为优先排查项，不要只检查网络连接
和测量启停状态。
